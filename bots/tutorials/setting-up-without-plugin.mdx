## Requirements

Before getting started, please ensure you have the following:

- A new or existing project, configured with your build system of choice.
- A Java Development Kit version compatible with Kord Extensions and your build system.

## Dependencies

Kord Extensions provides multiple dependencies, depending on what your project needs:

- **Annotation Processor:** `dev.kordex:annotation-processor` (KSP annotation processor required for a few things)
- **Core:** `dev.kordex:kord-extensions` (Required core module containing everything you need to write a Discord bot)
  - Includes the token parser, as well as ICU4J, JEmoji, Koin, Kord, KotlinLogging, kotlinx.serialization, OSHI, PF4J,
    Sentry, and TomlKt.
    If you need these in your project, don't add them to your dependencies — Kord Extensions will add them
    automatically.
- **Token Parser:** `dev.kordex:token-parser` (Library for parsing chat command strings into usable token streams)

It also provides many extra modules, split into categories.
For more information, see

## Build Configuration

<Tabs groupId="build-systems">
  <TabItem value="gradle-kotlin" label="Gradle (Kotlin)" default>
    Add the core dependency to your `gradle/libs.versions.toml` file.

    ```toml
    [versions]
    kord-extensions = "2.3.1-SNAPSHOT"

    [libraries]
    kord-extensions-core = { module = "dev.kordex:kord-extensions", version.ref = "kord-extensions" }
    kord-extensions-ap = { module = "dev.kordex:annotation-processor", version.ref = "kord-extensions" }
    ```

    Then, add the required Gradle plugins to your `build.gradle.kts` file.

    ```kotlin
    plugins {
      kotlin("jvm") version "2.1.20"
      kotlin("plugin.serialization") version "2.1.20"

      id("com.google.devtools.ksp") version "2.1.20-1.0.32"
    }
    ```

    Finally, add the required repositories and dependency to your `build.gradle.kts` file.

    ```kotlin
    repositories {
      // ...

      mavenCentral()

      maven {
        name = "KordEx (Snapshots)"
        url = uri("https://snapshots-repo.kordex.dev")
      }

      maven {
        name = "KordEx (Releases)"
        url = uri("https://releases-repo.kordex.dev")
      }

      maven {
        name = "Kord (Snapshots)"
        url = uri("https://repo.kord.dev/snapshots/")
      }
    }

    dependencies {
      // ...

      implementation(libs.kord.extensions.core)
      ksp(libs.kord.extensions.ap)
    }
    ```

  </TabItem>

    ```scala
    enablePlugins(KotlinPlugin)

    kotlinLib("stdlib")
    kotlinPlugin("serialization")

    resolvers += "KordEx (Snapshots)" at "https://snapshots-repo.kordex.dev"
    resolvers += "KordEx (Releases)" at "https://releases-repo.kordex.dev"

    libraryDependencies ++= Seq(
        "dev.kordex" % "kord-extensions" % "2.3.1-SNAPSHOT"
    )
    ```

## Resource Files

The KordEx Gradle plugin normally generates some `.properties` files to be included with your bot.
These files provide some additional configuration options, as well as bundling some version information with your bot.

### Build Properties

You can add some properties to `src/main/resources/kordex-build.properties`.

**You must provide the following properties** — failing to do so will break the plugin system:

- `versions.kordex` - The version of Kord Extensions used to build your bot.
  - Used by the plugin system to figure out plugin compatibility, as well as logging and data collection.
  - If you're using Gradle, we strongly recommend generating this file and getting the version from
    `libs.versions.kord.extensions.core`.
  - May instead be provided in `kordex.properties` if you prefer.

The following properties are optional, and failing to provide them won't break anything other than a log message:

- `git.branch` - The Git branch used to build the version of Kord Extensions your bot uses.
  - Used exclusively for logging.
- `git.hash` - The Git commit used to build the version of Kord Extensions your bot uses.
  - Used exclusively for logging.
- `versions.kord` - The version of Kord used to build your bot.
  - Used exclusively for logging and data collection.

### Bot Settings

You can add some properties to `src/main/resources/kordex.properties`.

The following properties are optional, and failing to provide them won't break anything:

- `modules` - List of first-party Kord Extensions modules used by your bot.
  - Used exclusively for data collection.
- `settings.dataCollection` - Data collection level, one of `none`, `minimal`, `standard` or `extra`.
  - May also be provided using the `dataCollection` system property or `DATA_COLLECTION` environmental variable.
  - Defaults to `standard` if not provided.
- `versions.bot` - Your bot's version.
  - Used exclusively to provide a default value for `botVersion` in your bot's configuration builder.
- `versions.kordEx` - Alternative to the same key in `kordex-build.properties`.
  - Used by the plugin system to figure out plugin compatibility, as well as logging and data collection.
- `versions.kord` - Alternative to the same key in `kordex-build.properties`.
  - Used exclusively for logging and data collection.
  - Was previously `kordVersion`, a property still supported as an alternative for legacy reasons.
