# Messages: Easy DSL

Messages support a specific set of components, which you can read about [on the basics page](/bots/components/basics).

The components DSL (based on the `ComponentContainer` class) is a convenient API for working with short-lived message
components.

If you need your components to work after your bot restarts, we recommend [using the manual handling approach](#).

:::tip No Atomic API

Kord Extensions doesn't provide an atomic API for modifying your components after you've sent them to Discord.
This is mostly due to technical limitations within Kotlin's type system,
and it is unlikely this will change any time soon.

If you wish to edit components, we suggest keeping a reference to the `ComponentContainer` returned by the `components`
builder, and any relevant components that you create.
The components within any given `ComponentContainer` may be applied to any message creation/editing builder via the
`applyComponents` extension function.

:::

## Usage

To get started, use the `components` builder in any message creation or editing builder.
This builder will automatically add the defined components to the message, and set up the code necessary for your bot
to respond to them.

```kt
respond {
	components {
		publicButton {
			label = "Button"
			style = ButtonStyle.Primary

			action {
				respond {
					content = "Clicked button."
				}
			}
		}
	}
}
```

The above example produces a message like the following:

<MessageContainer>
  <Message>
    <ActionRow>
      <Button label="Button" style="primary"/>
    </ActionRow>
  </Message>
</MessageContainer>

For more information on what components you can add with this DSL, see the builder API section below.

## Packing

The `components` DSL automatically packs its defined components as tightly as possible, while retaining the order you
defined them in.

As an example, let's say you provided a select menu, six buttons, and another select menu.
The resulting message would look like this:

<MessageContainer>
  <Message>
    <ActionRow>
      <SelectMenu label="Select Menu"/>
    </ActionRow>

    <ActionRow>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
    </ActionRow>

    <ActionRow>
      <Button label="Button" style="primary"/>
    </ActionRow>

    <ActionRow>
      <SelectMenu label="Select Menu"/>
    </ActionRow>
  </Message>
</MessageContainer>

You can prevent this for specific components by specifying the row to add your component to — just pass an integer
representing the row to the corresponding component builder function.
This will add that component to the specified row immediately, and the builder will pack any components without defined
rows around it before your bot finishes creating the message.

As an example, let's say you provided a select menu on row 2, six buttons without row numbers, and another select
menu on row 3.
The resulting message would look like this:

<MessageContainer>
  <Message>
    <ActionRow>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
      <Button label="Button" style="primary"/>
    </ActionRow>

    <ActionRow>
      <SelectMenu label="Select Menu"/>
    </ActionRow>

    <ActionRow>
      <SelectMenu label="Select Menu"/>
    </ActionRow>

    <ActionRow>
      <Button label="Button" style="primary"/>
    </ActionRow>
  </Message>
</MessageContainer>

## Container API

<Doc.Container>
  <Doc.Type name="ComponentContainer" type="class" extends="KordExKoinComponent" open>
    Class representing a single set of components to apply to any message.

    <Doc.Arguments type="constructor">
      <Doc.Arg name="timeout" type="Duration?" default="null" propType="val">
        Optional timeout, after which all registered components will be unregistered and won't work anymore.
        This timeout is reset whenever a user interacts with a registered component.
      </Doc.Arg>

      <Doc.Arg name="startNow" type="Boolean" default="false">
        Whether to start the timeout immediately.
        This is usually set to `true` by the `components { }` DSL, but you can call `timeoutTask.start()` yourself
        in other situations.
      </Doc.Arg>
    </Doc.Arguments>
  </Doc.Type>
</Doc.Container>

### Builders

<Doc.Container>
  <Doc.Builder name="onTimeout" receiver="ComponentContainer" open>
    Register a callback to be run when the `timeout` expires, if one was provided.

    Component containers can only have one registered callback.
    Calling this function twice will overwrite the previous one.
  </Doc.Builder>
</Doc.Container>

### Functions

<Doc.Container>
  <Doc.Function name="cancel" open suspend>
    Cancel the timeout task and remove all stored components, unregistering them.

    This behaviour is similar to letting the timeout expire, but **it won't run the extra `timeoutCallback` provided by
    the `onTimeout { }` builder.**
  </Doc.Function>

  <Doc.Function name="remove" open suspend>
    Remove a component from this container, and unregister it.

    <Doc.Arguments>
      <Doc.Arg name="component" type="Component">
        Component to remove.
      </Doc.Arg>
    </Doc.Arguments>
  </Doc.Function>

  <Doc.Function name="removeAll" open suspend>
    Remove all components from this container, and unregister them.
  </Doc.Function>

  <Doc.Function name="replace" open suspend>
    Remove a component from this container, replacing it with a new one and likewise handling un/registration.

    <Doc.Arguments>
      <Doc.Arg name="old" type={["Component", "String"]}>
        The component to remove.
        You can provide the component object, or a `String` representing its ID.
      </Doc.Arg>

      <Doc.Arg name="new" type="Component">
        The component to replace with.
      </Doc.Arg>
    </Doc.Arguments>
  </Doc.Function>

  <Doc.Function name="sort" open suspend>
    Sort any unsorted components into `rows`, by packing them as tightly as possible.
  </Doc.Function>
</Doc.Container>

<Doc.Container internal>
  <Doc.Function name="add" open suspend internal>
    Add a component to this container, and register it.

    This is usually called by the [builder functions](#builder-functions).

    <Doc.Arguments>
      <Doc.Arg name="component" type="Component">
        Component to add.
      </Doc.Arg>

      <Doc.Arg name="rowNum" type="Int?" default="null">
        Optional row to pack the component into.

        If you provide a row number, the component will immediately be packed into the corresponding list in `rows`.
        Otherwise, it'll be added to `unsortedComponents` for the `sort()` function to handle later.
      </Doc.Arg>
    </Doc.Arguments>
  </Doc.Function>
</Doc.Container>

### Properties

<Doc.Container>
  <Doc.Property name="timeoutTask" type="Task?" propType="val" visibility="public" open>
    Timeout task, responsible for enforcing the provided `timeout`.
    This will be `null` if no `timeout` was provided.
  </Doc.Property>
</Doc.Container>

<Doc.Container internal>
  <Doc.Property name="rows" type="Array<MutableList<Component>>" propType="val" visibility="public" open internal>
    Array representing up to five rows of sorted and packed components.

    This array always contains five mutable lists, which are filled by the `sort()` function.
  </Doc.Property>

  <Doc.Property name="timeoutCallback" type="(suspend (ComponentContainer).() -> Unit)?" default="null" propType="var" visibility="public" open internal>
    Extra callback to run when the `timeout` expires, if one was provided.

    Usually set via the `onTimeout { }` builder.
  </Doc.Property>

  <Doc.Property name="unsortedComponents" type="MutableList<Component>" propType="val" visibility="public" open internal>
    List containing all components without an explicitly defined `row`, to be packed into `rows` before adding the
    components to a message.
  </Doc.Property>
</Doc.Container>

## Component Contexts

All component `action { }` blocks use a corresponding context object as the receiver, allowing you to retrieve any
relevant data and respond to component interactions.

<Doc.Container>
  <Doc.Type name="ComponentContext" type="abstract class" extends={["KordExKoinComponent", "TranslatableContext"]}>
    Class representing a basic component context, with functionality common to all contexts.

    <Doc.Arguments type="type">
      <Doc.Arg name="E" type="ComoponentInteractionCreateEvent">
        Generic type representing the event that triggered this interaction.
      </Doc.Arg>
    </Doc.Arguments>

    <Doc.Arguments type="constructor">
      <Doc.Arg name="component" type="Component">
        Component object corresponding with this interaction.
      </Doc.Arg>

      <Doc.Arg name="event" type="E">
        Object representing the event that triggered this interaction.
      </Doc.Arg>

      <Doc.Arg name="cache" type="MutableMap<String, Any>">
        Data cache map shared with this command's [checks](/bots/checks).
      </Doc.Arg>
    </Doc.Arguments>

    <Doc.Property name="channel" type="MessageChannelBehavior" propType="var" open>
      The channel this component interaction happened in.
    </Doc.Property>

    <Doc.Property name="guild" type="GuildBehavior?" propType="var" open>

    </Doc.Property>

    <Doc.Property name="member" type="MemberBehavior?" propType="var" open>
      The guild member that caused this component interaction, or `null` if

    </Doc.Property>

    </Doc.Property>

    </Doc.Property>
  </Doc.Type>
</Doc.Container>

### Select Menus

Select menus use a context type extending the above, with some small additions:

- **Channel Menus:**
  - A `selected` property containing the selected channels.
- **Mentionable Menus:**
  - A `selected` property containing the IDs of all selected users and roles.
  - A `selectedRoles` property containing the selected roles.
  - A `selectedUsers` property containing the selected users.
- **Role Menus:**
  - A `selected` property containing the selected roles.
- **String Menus:**
  - A `selected` property containing the selected option strings.
- **String Menus:**
  - A `selected` property containing the selected users.
